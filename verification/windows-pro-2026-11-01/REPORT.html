Aplicativo Electron com instalador por usuário, cartão flutuante nativo, bandeja e atalhos; plugin C++ com SCS SDK 1.16; autenticação externa com PKCE; diário local durável; integração com a fila canônica da NVU e validação transacional no servidor. O código, o SDK com sua licença e os comandos de build estão no projeto completo.

As verificações executadas permitem entregar uma versão candidata. Não foi executado Windows real, login Google de produção ou uma viagem dentro dos jogos. A ausência dessas verificações impede declarar a versão pronta para produção.

Configuração do login Windows

O cliente OAuth Desktop fornecido pelo proprietário foi incorporado ao instalador 0.1.1. O JSON foi conferido como tipo installed, associado ao projeto vtc-frota-log, com endpoints oficiais do Google. A configuração extraída do aplicativo empacotado corresponde à configuração fornecida.

Consulta autenticada e somente de leitura à API oficial do Firebase confirmou que o provedor Google está habilitado e que o cliente principal pertence ao mesmo projeto. O cliente Web do provedor foi preservado. Esses metadados não comprovam aceitação de um token Desktop, login de usuário, preservação de UID, renovação ou logout: essas verificações continuam pendentes.

O aplicativo abre o navegador do sistema e recebe o retorno de loopback com PKCE, state e nonce. A configuração de aplicativo Desktop é pública; tokens de usuário são gerados somente ao entrar e são protegidos pelo armazenamento do Windows. Referências: OAuth Desktop e configuração de provedores Firebase.

O que falta para aprovar

  1. Instalar no Windows x64, entrar com a conta Google habitual e confirmar a mesma identidade Firebase, os vínculos existentes, a restauração e o logout.
  2. Validar a matriz de ETS2/ATS descrita no guia: entrega real, cancelamento, Alt+Tab, reconexão, perda de rede/ACK, reinício, DPI e monitores.
  3. Configurar assinatura Authenticode legítima para distribuição pública. Este instalador e a DLL não foram assinados.

Este instalador substitui a candidata 0.1.0 sem configuração OAuth. A versão 0.1.1 inclui o cliente Desktop real e tem um novo checksum. As funções publicadas anteriormente foram preservadas.

Falha NSIS relatada e entrega alternativa

A captura do usuário mostra uma falha de integridade. O arquivo gerado e a cópia recuperada do arquivo disponibilizado foram comparados: ambos têm 125712878 bytes e o mesmo SHA-256. O CRC interno nativo NSIS, 8717188d, também confere. O EXE efetivamente baixado no PC do usuário não foi recebido; a causa local continua sem confirmação.

A versão NVU-PRO-Windows-0.1.1-x64-Portable.zip contém o aplicativo completo. Extraia todo o ZIP e abra NVU PRO.exe dentro da pasta extraída. Ela permite testar o aplicativo sem executar o instalador e usa os mesmos dados em %APPDATA%\NVU PRO.

A alternativa NVU-PRO-Windows-0.1.1-Instalador.zip contém o EXE original íntegro com nome curto, NVU-Setup.exe, instruções e checksum. O build foi reforçado para bloquear CRC nativo inválido antes de gerar uma entrega. Nenhuma proteção de integridade foi desativada. Evidências em verification/windows-installer-recovery-2026-11-01.

Os novos ZIPs são alternativas de entrega. Sua extração e seus bytes foram conferidos; a execução no Windows, o login real e os jogos continuam pendentes. O incidente não foi marcado como resolvido no PC sem essa confirmação.

Segurança e limites

Renderer isolado e sem Node, sandbox, CSP, navegação restrita, IPC limitado, arquivos locais com ACL por usuário, token de ponte e heartbeat. Login externo com PKCE/state/nonce, assinatura e audience do ID token verificadas; renovação protegida pelo armazenamento do Windows. O servidor continua responsável por vínculo, coerência, simulador, capacidade e idempotência.

Telemetria é classificada como client_reported_sdk, não como comprovante inviolável. O UUID persistido identifica a mesma captura e seus replays; não prova a unicidade de um frete entre instalações independentes ou saves manipulados. Dados incompletos ficam em conferência, com acesso ao lançamento existente com OCR.

npm audit do pacote Windows: 0 alertas nas dependências de produção; 15 alertas moderados na árvore de build, originados no minimatch < 11.0.1 e propagados por dependências do empacotador. Não houve downgrade ou alteração forçada incompatível para ocultar o achado. A auditoria não equivale a uma revisão exaustiva de todas as dependências preexistentes da NVU.

Priorize janela sem bordas. Tela cheia exclusiva, versões modificadas e TruckersMP exigem validação própria. O aplicativo não injeta renderização, altera executáveis dos jogos ou desativa proteções do Windows.

Uso e compilação

  1. Instale a candidata 0.1.1 por usuário e entre com a conta Google que já usa na NVU. A configuração OAuth acompanha esta edição.
  2. Abra PRO Windows, localize os jogos, instale o plugin com o jogo fechado e reinicie o simulador.
  3. Selecione uma operação iniciada do simulador correto e ative PRO. O frete atual será vinculado àquela operação.
  4. Ctrl+Alt+N mostra/oculta o cartão; Ctrl+Alt+P abre o painel. A bandeja permite reabrir e sair.
